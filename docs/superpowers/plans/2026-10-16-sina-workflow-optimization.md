# SINA 整体识别工作流优化方案

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 以 YOLO11m 为默认元件检测器，提高电路识别的编号、数值、引脚和连接正确率，交付可复核、可集成的识别模块。

**Architecture:** 原图及坐标变换 → YOLO11m 元件检测 → OCR 文字识别 → 引脚与导线分析 → 电路图结构 → Pro 定点复核 → 校验后的统一电路 JSON → 网表生成接口。视觉模型的建议保留证据，未知信息保持未知。

**Tech Stack:** 当前独立环境中的 Ultralytics YOLO11m、EasyOCR、OpenCV/CCL、豆包 Pro、Python JSON 校验；有证据需要时再增加引脚关键点模型。

**Spec:** 用户要求保留 YOLO11m，并制定整体工作流各部分的优化方案；本计划结合 `训练结果与交付.md`、`完整工作流模型对照结果.md` 及七轮 Pro 直接检测实验。这里的任务尚未实施，不能将优化目标当成已达到指标。

**GUI 架构更新：** 用户随后提供 LabPilot-GUI，现已完成共享 `gui_workflow.py` 入口、`gui_contract.py` 数据契约、GUI JSON v2、阶段证据、人工确认校验及便携包集成。实际接口见 `LabPilot-GUI/WORKFLOW-INTERFACE.md`。本计划中的检测精度、OCR、引脚与连接算法优化仍未因此完成，不能将接口联通当作准确率提升。

## 已知条件与决策依据

- 原数据：596 张训练图，66 张验证图，十类元件；现有标注主要是类别和矩形框，没有完整 OCR、语义引脚及电路连接标准答案。
- YOLO11m：作者电路权重经过本工作台再微调，原验证集 mAP50=97.14%、mAP50–95=74.54%。固定 conf=0.25、960 输入下，TP=687、FP=50、FN=20，F1=95.15%。这些指标不能混称为整图准确率。
- 原数据的初始权重与验证集有历史关联，本轮也使用验证集挑权重；缺少独立真实图片测试集。感知哈希发现的相似候选还需人工确认，不能直接宣称泄漏或自动删掉。
- 已观察到：R1/R2/RC 编号误配；CCL 漏掉三极管开放基极；MOS 几何触点顺序没有转为 D/G/S/B；不准确的框会导致电阻接触点数异常；原版网表提示词可能遗漏 `.end` 或补出未经确认的模型。
- YOLO26l 实验已按用户要求停止，不能将中途权重报告为最终训练结果。默认继续使用 YOLO11m。
- 七轮 Pro 直接检测对照已完成：同一 66 图重复七次，包含失败输出的平均 F1（IoU≥0.5）为 67.21%，YOLO11m 为 95.15%；Pro 胜出 0/7 轮。保留 YOLO11m。完整证据在 `runs/pro-direct-seven-trials-20261016/comparison.json` 与 `Pro直接检测七轮对照结果.md`，这些不是独立测试集或完整电路识别指标。

## Global Constraints

- 原始图片、原版权重和上游代码快照保留；训练和实验使用新目录。
- 不把 Pro 的自评置信度、接口成功或网表能运行当成人工准确率。
- 保留 OCR 原文，未知参数不猜测，未确认引脚不能静默接到最近导线。
- 模型选择只使用开发/验证数据；独立最终测试集冻结，不能每轮用它调参。
- 一个实验只改变一个主要模块，其余配置、图片集合与评分规则固定；记录数据/权重/提示词哈希。
- 对外结果保持兼容，新增证据字段；未通过语义和连接检查保持 `ready_for_simulation=false`。
- 密钥仅使用环境变量或本地忽略文件，不进入训练样本、报告或交付包。

## Review Focus

- 模糊、倾斜、不同符号风格和密集大图：记录处理前后效果，不能让预处理抹掉细导线。
- 无标号元件、开放引脚和文字式供电：分别表示，不补成假元件或假连接。
- 导线交叉、T 接点和连接点圆点：连接与不连接必须有明确证据。
- 单位大小写、下标位号和重复标签：保留原文并检查一对一匹配，不能全转大写。
- API 超时、非法格式和建议改动连接：拒绝自动采用，保留失败与原始证据。

## 目标工作流

```text
电路原图 → 质量检查/坐标变换 → YOLO11m 元件框
                              ├→ 局部 OCR → 文字与元件匹配
                              └→ 引脚定位 → 导线提取/交点判断
                                         ↓
                       元件—语义引脚—网络节点的结构化图
                                         ↓
                   Pro 对低置信度项定点复核 + 人工确认入口
                                         ↓
                  规则校验 → 统一电路 JSON → 网表生成模块
```

## 任务 1：建立可信数据与评测基线（P0）

**Files:** 新建 `tools/audit_annotations.py`、`tools/evaluate_pipeline.py`、`datasets/recognition/manifest.json`；复用 `tools/validate_on_dataset.py`、`runs/round-002/`。

**Interfaces:** 数据清单记录 image_id、来源、split、sha256、标注版本；完整参考答案覆盖元件框、编号、原始数值/单位、引脚语义和网络连接。

- [ ] 人工复查 20 个漏检和 50 个误检，区分模型错误、漏标及类别定义问题。
- [ ] 核验跨 split 的相似图候选，按原始电路/出处分组划分，避免同图变体跨集合。
- [ ] 首批建议人工标注 50 张代表性电路作为开发难例，覆盖 BJT、MOS、交叉线、低清晰度；这是工作量建议，不是已存在的数据。
- [ ] 另外建立至少 50 张不同来源的最终测试图，冻结不参与调参；数量不足时明确限定结论范围。
- [ ] 对每张图逐层计分：检测 P/R/F1 与 mAP、位号绑定率、数值+单位正确率、引脚语义正确率、网络连接 F1、全图结构正确率、人工修正次数和耗时。
- [ ] 测试参考节点编号整体重命名后评分不变；串换 B/C/E 必须判错；电阻两端交换可以等价，二极管和晶体管端子不能随意交换。

**验收:** 数据来源和划分可追溯；人工参考答案与模型输入隔离；所有失败保留在完整分母中。

## 任务 2：优化 YOLO11m 检测（P1）

**Files:** 调整 `tools/train_round.py`，新建 `experiments/yolo11m-tuning/` 的配置与结果；不覆盖 round-002 权重。

**Interfaces:** 继续输出现有十类 `id/type/bbox/confidence`，记录原图坐标和模型哈希；下游不依赖检测结果的返回顺序。

- [ ] 先修标注，再针对电容、接地、二极管、小目标和相似符号补充难例。
- [ ] 固定现有权重作基线，顺序试验 960 与 1280 输入；16GB 显存下逐步确定 batch，不预先保证大批次能运行。
- [ ] 对密集大图单独测试重叠分块推理和跨块去重，检查边缘元件不会被重复或切断。
- [ ] 在开发集调整分类阈值与 NMS，评估降低漏检的同时是否增加大量误检；不使用最终测试集寻找阈值。
- [ ] 在整理过的数据上微调现有电路权重，优先比较少量有理由的学习率与早停配置，避免无目标地反复训练。
- [ ] 增强以合理的缩放、平移、模糊、压缩和亮度变化为主；旋转/翻转必须验证符号语义及引脚标签变换，不默认开启。
- [ ] 检查框定位 IoU 和框边缘到真实引脚的距离；元件分类对但框不准，不能自动通过下游验收。

**验收:** 开发集主要指标提升，弱类和漏检没有不可接受的退步，连接分析不因框变化明显变差；最后在冻结测试集上报告一次结果。目标数值需基线测完后确定，不承诺“达到 99%”。

## 任务 3：输入预处理和 OCR 匹配（P1/P2）

**Files:** 新建 `tools/image_preprocess.py`、`tools/text_assignment.py`；调整 `tools/local_extract.py` 的 OCR 分支。

**Interfaces:** 预处理提供坐标变换和逆变换；OCR 同时保存 `text_raw/bbox/confidence`，解析结果另存，不覆盖原文。

- [ ] 先检测图片尺寸、模糊与倾斜；对需要的图执行去倾斜和温和增强，保留原图，检查细线未消失。
- [ ] EasyOCR 作为主 OCR，比较全图识别与元件附近放大裁剪；避免把元件本体一并识别成字母。
- [ ] 保留 `R_C`、`R₁` 等原文并建立规范位号字段；数值与单位分别解析，测试 `1kΩ`、`100nF`、`4.7uF` 和 `m/M/meg` 的约定，导出 SPICE 时再按其规则转换。
- [ ] 将当前“最近三段文字候选”升级为考虑方向、距离、元件类别和一对一约束的匹配；文本可能同时属于型号和位号，不强迫所有文字都匹配。
- [ ] 歧义项交给 Pro 看局部裁剪和带 id 的原图，明确允许返回未知；不让 Pro 默认重写所有已确定结果。
- [ ] 若 EasyOCR 在人工难例上仍差，再评估其他 OCR；不在未测量前替换整个引擎。

**验收:** 数值准确性按“正确元件+数值+单位”联合评分；未知值不被补造；相邻元件的标签交换必须被测试检出。

## 任务 4：引脚定位与语义（最高价值的 P1）

**Files:** 新建 `tools/pin_analysis.py`、`datasets/pins/`；调整 `tools/local_extract.py`、`tools/training_contract.py`。

**Interfaces:** 保留现有 `pin_candidates`，新增每个引脚的 `image_point/semantic/net_id/evidence/status`。几何顺序与 SPICE 端子顺序分开表示。

- [ ] 检查元件掩膜和边缘接触点提取，开放引脚即使没有连接其他元件也应保留，不能因为接触对象少就删除。
- [ ] 按类别做几何引脚数量检查：电阻/电容/二极管通常两个触点，BJT 通常三个；MOS 的可见端子和隐含体端需分别记录，运放需按符号形式处理，不能机械套一个数字。
- [ ] 用符号方向、箭头和形状建立 B/C/E、G/D/S、A/K 的候选语义，歧义保留，不用左右上下顺序直接当语义顺序。
- [ ] 修复现有 BJT 开放基极和 MOS 顺序难例；局部 Pro 复核只提供建议，不静默把缺失基极连到地。
- [ ] 若规则定位仍不稳定，新增真实引脚关键点标注，训练 YOLO11 系列的引脚关键点分支或局部关键点模型。现有框标注无法直接监督这个任务，人体关键点预训练模型也不能直接识别电路端子。
- [ ] 测试开放基极、镜像/旋转符号、隐含 MOS 体端和两引脚接错网络的情况。

**验收:** 引脚数量完整，语义准确率与接线准确率单独报告；不得通过填充重复节点掩盖缺引脚。

官方关键点任务说明：https://docs.ultralytics.com/tasks/pose/ 。这里借用的是关键点训练能力，仍需自行定义电路引脚标注。

## 任务 5：导线、交叉点与图结构（P1/P2）

**Files:** 新建工作台自有 `tools/wire_graph.py`、`tools/junction_analysis.py`，以适配层调用上游，避免直接改上游快照。

**Interfaces:** 输出 `nets`、引脚到 net 的映射、交点候选及连接/不连接证据；节点 id 只是标识，不依赖固定整数。

- [ ] 在原图副本上去除元件本体和已确认文字，避免擦掉真实导线；测试元件框微调后连接是否稳定。
- [ ] 对比固定阈值、自适应阈值及有限的断线修复；骨架化后提取线段和端点，防止过度膨胀把邻近线路粘在一起。
- [ ] OpenCV CCL 保留为基础工具，单独处理 T 接、圆点交点、无圆点跨线和桥形跨线，不能将所有几何交叉视为连接。
- [ ] 引脚吸附使用明确距离限制与候选证据，尺度变化时做相应归一化；超出范围保持开放或待确认，不能吸到任意最近线。
- [ ] 用可解释图结构合并同一导线网络；节点编号变化不算电路改变，端子网络发生改变必须算错。
- [ ] 交叉歧义生成多个局部候选供 Pro/人工选择，不能通过常见电路模板强行补线。

**验收:** 以人工网络图评测连接边的 P/R/F1；开放引脚和无连接交叉不被自动短接。

OpenCV 连通域接口说明：https://docs.opencv.org/4.x/d3/dc0/group__imgproc__shape.html 。CCL 是图像连通分析，不直接理解电气引脚语义。

- [ ] 在图上叠加唯一 id 和框，再提供局部裁剪，减少靠内部编号猜实际 R1/R2 的错误。
- [ ] 按任务拆开：位号/参数匹配、引脚语义和交叉歧义，不在同一回复中要求它自由重建全部电路。

- [ ] 网络/服务错误与识别错误分开统计；重试需有次数上限、日志与费用统计，不能无限请求直到碰到好答案。
- [ ] 如果建议修改连接，生成差异与理由，保留原候选，经过校验/人工确认再采用。
- [ ] 用固定开发难例做新旧提示词比较，保留原版文本及来源；复核模型自己不能充当正确率裁判。

**验收:** R1/R2/RC 对应错误减少；API 失败可恢复或明确转人工，所有修改可追溯。

## 任务 7：统一数据、网表校验与小组交付（P0/P2）

**Files:** 新建 `tools/circuit_validation.py`、`schemas/circuit.schema.json`，完善 `tools/assemble_delivery.py` 与接口说明；网表/仿真模块由小组约定负责人对接。

**Interfaces:** 对外保留 components/ocr/warnings，明确区分原始识别、模型建议和已确认值；新增 net/pin/evidence 与状态字段。提供本地函数/CLI，后续按小组环境包装 HTTP 服务。

- [ ] 在调用网表整理前检查非法引脚数量、重复位号、未知连接和单位；结构错误不能继续生成看似正常的 `.cir`。
- [ ] 网表导出按元件语义端子顺序组装，统一接地节点 0，检查 `.end`、参数和真实模型定义；MOS 体端策略必须显式配置。
- [ ] 缺型号、缺真实数值时输出待确认原因，不使用固定通用模型冒充识别结果。
- [ ] 将网表语法通过、仿真能运行和识别正确率分开统计；能仿真不代表识别与原图一致。
- [ ] 交付权重、类别表、依赖锁定、推理入口、JSON Schema、示例输出、人工评测报告和失败样例；密钥不入包。
- [ ] 回归测试覆盖重复编号、非法引脚数、单位误读、跨线短接和丢失电源条件。

**验收:** 小组成员用自己的环境与密钥可重复运行；每项未知和每条改动都有证据，仿真模块不需要猜识别结果的含义。

## 建议执行顺序

1. 固化基线和人工难例，先补引脚/网表拒绝规则，避免错误继续流入后续模块。
2. 清理标注并优化 YOLO11m，同时修复开放基极、掩膜和几何接触点问题。
3. 优化 OCR 裁剪、单位解析和文字一对一匹配。
4. 做交叉线与网络图重建，再测试局部 Pro 复核。
5. 统一接口和小组交付，最后在冻结独立测试集验收。

建议首轮聚焦前三项。是否进入关键点训练，依据规则修复后的引脚错误占比决定，避免在没有关键点标注时盲目启动训练。
