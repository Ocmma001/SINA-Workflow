# Lite / Pro 完整识别工作流

GUI 集成更新：界面与命令行共用的主入口现为 `tools/gui_workflow.py`，输出可编辑 JSON v2，再经人工确认进入仿真。接口见 `LabPilot-GUI/WORKFLOW-INTERFACE.md`。下面的 `run_workflow.py` 和文字网表路线保留作原版提示词与双模型研究对照，不作为 GUI 填表的主入口。

统一入口：`tools/run_workflow.py`。默认选择 Pro，保留 Lite 可切换。

流程：电路图片 → 已训练检测器 → 上游连接分析与 EasyOCR → 原版 SINA 元件清单提示词 → 原版 SINA 网表提示词（加入元件坐标和原图）→ 网表草稿与校验报告。

此入口不使用人工修订的连接关系，也不重新训练检测器或豆包模型。豆包部分使用 API 推理。密钥从工作台根目录 `.env` 的 `ARK_API_KEY` 加载；选择的 profile 会明确指定对应模型，覆盖环境中的 ARK_MODEL。

在 `D:\learn\LabPilot-2026-10-15` 执行，替换图片路径，输出目录必须不存在：

```powershell
.\SINA-Workbench\SINA-venv\Scripts\python.exe .\SINA-Workbench\tools\run_workflow.py "D:\你的图片.jpg" --out ".\SINA-Workbench\runs\my-pro-run" --profile pro
```

使用 Lite：将 `--profile pro` 改为 `--profile lite`，并使用新的输出目录。

输出包括：

- `local/recognized.json`：元件框、OCR、引脚与连接候选。
- `local/detected.jpg` 和 `local/debug/`：检测及连接分析可视化。
- `pro/` 或 `lite/`：两阶段识别文本、`sina-draft.cir` 和 `sina-ark-result.json`。
- `workflow.json`：此次选择的模型与流程说明。

`ready_for_simulation` 始终为 false；查看 `netlist_validation_issues` 并确认参数和引脚后再交给仿真模块。原图未给出的阻值不能凭空补成可仿真参数。

对照实验复现：

```powershell
.\SINA-Workbench\SINA-venv\Scripts\python.exe .\SINA-Workbench\tools\workflow_benchmark.py --name workflow-my-comparison --repeats 3
```

对照实验为每张图重新运行本地识别，然后让两个 API 共享相同本地证据，确保公平。人工答案只用于评分，不作为模型输入。样本只有两张，不代表独立测试集准确率。
