# SINA 电路原理图识别完整工作流

核对日期：2026-10-16。上游：<https://github.com/medal-ece/SINA>。
固定版本：`a4f138852d40004ffdb4f69a67a27250c4d44db7`。以此版本 IC 模块源码为准，旧交接中的原电脑环境与 DeepSeek 改造不能直接套用。

## 一、目标与边界

输入是二维电路原理图的截图、扫描件或照片，输出是元件与连接关系的识别结果、调试图片和网表文本。实物电路照片、面包板接线不是本 IC 流程已验证的输入。

你要优化的完整链路：

```text
原理图图片与人工标准答案
    ↓
输入检查与实验版本记录
    ↓
YOLO 元件检测
    ↓
图像二值化、导线/节点分析、引脚定位与交叉线处理
    ↓
OCR 提取文本并关联元件 + 在线视觉模型识别
    ↓
候选确认（上游当前未执行有效的数量一致性拒绝）
    ↓
元件引脚映射到连通区域 → 结构网表
    ↓
模型结合结构、OCR 和视觉输出分配位号/生成最终网表
    ↓
人工真值对照：元件 → 数值 → 引脚 → 连接 → 整图
    ↓
归档错误 → 修改单一因素 → 验证集回归 → 独立测试集验收
```

本任务到识别评估为止，不调用 ngspice。网表生成完成不等于网表正确，也不等于可直接仿真。

## 二、准备环境与基线

1. 查看工作区 `UPSTREAM.json`，确认 `complete` 为 true，记录 commit；下载是官方固定版本文件快照，不包含完整 Git 历史。
2. 官方 IC README 要求 Python 3.12；历史交接验证过 3.11。目前机器默认 3.13 尚未验证。本轮建议建立独立 3.12 环境，按上游 requirements 安装并记录实际版本。
3. 准备两个 easyocr 模型 `craft_mlt_25k.pth`、`english_g2.pth`；Tesseract 为辅助 OCR，准备英文语言数据。
4. 当前官方代码使用 `OPENAI_API_KEY`，固定调用 OpenAI 的 `gpt-4o` 和官方端点。历史的 `SINA_API_BASE`、`SINA_API_MODEL`、`SINA_DISABLE_THINKING` 不会自动改写原版请求。
5. 基线阶段固定 YOLO 权重、图片、硬件、依赖、提示词与阈值。官方入口选择编号最大的 `train*` 目录中的 `last.pt`，不是自动选择 `best.pt`。

克隆/下载和安装依赖不等于已经跑通识别；本机实跑状态单独记录。

## 三、识别执行的具体步骤

所有相对路径以 `SINA/Netlist Generator/IC/program_test/netlist_generator_algorithm_test/` 为根。

### 1. 输入图片

图片放入 `inputs/test_images/`。先核对图像可读性、分辨率、旋转、裁剪、电源和地是否完整；预处理变体与原图分别保留。原版会批量处理入口目录，因此不要混入上一轮图片。

输出：固定图片清单、原图及其哈希、实验编号。

### 2. 检测元件

`helper_files/process_images.py` 用 YOLO 识别元件类别和边界框，创建 `Resistor_1` 等内部 ID。

这一步回答“哪里有什么元件”，不保证识别出图中的 `R1`、`10k`，也不代表连接已正确。

检查：漏检、误检、类别混淆、边框截断；尤其关注电源、地、竖直电阻和小符号。

典型产物：`2_model_detected_boxes.png`。

### 3. 图像与连接分析

原版将图像灰度化，使用固定阈值 150 二值化、3×3 核膨胀，然后调用 `nodes_analysis.py` 进行节点与连接分析。导线交叉处理使用 `find_crossing.py` 及后续消歧逻辑。

输出包括元件边界框、图像中的引脚坐标、连通区域与交叉信息。主要文件：

- `circuit_info.json`：元件 ID、类别、边界框、`connection_points`。
- `node_labels.npy`：像素区域的节点标签。
- `crossing_data.json`：交叉线信息（取决于图片与执行分支）。

检查：空连接点、引脚投到错误导线、细线断裂、文字被当成导线、交叉误判成连接。引脚坐标不等于 B/C/E 或运放正负输入等语义。

### 4. OCR 与在线视觉识别

`ocr_module.py` 提取文本，并通过 `proximity_analysis.py` 将邻近文本与元件关联，产生位号和数值候选。

**开启 OCR 的第一阶段也会调用在线视觉 API**：`process_circuit_ocr()` 调用 `extract_components_from_image_api()`，所以当前包装脚本的阶段 1 不是完全离线流程。

典型产物：

- `ocr_results.json`：OCR 文本、置信度与 `text_by_component` 候选映射。
- `ocr_results/circuit_components_with_text.txt`：后续网表生成实际读取的文本。
- `API_first_response.txt`：第一轮视觉模型输出。

注意：当前 `generate_all_netlists()` 读取上述文本文件，不能认为最终生成自动利用了 `ocr_results.json` 的所有字段。

检查：`1k/10k`、`u/n/p`、小数点、重复位号、模型空正文与文本归属错误。原始 OCR 与模型结果均保留，便于定位哪一步引入错误。

### 5. 候选通过与人工检查

`ocr_module.py` 的 `check_component_consistency()` 当前将 `passed` 设为 true，但比较数量与拒绝逻辑被注释掉。它可能把图片放入 `outputs/approved_images/`，**不能把这个目录当成识别正确证明**。

`process_images.py` 还有同名检查函数，但本流程中 OCR 调用的是 `ocr_module.py` 里的版本。

调优阶段应人工检查元件是否齐全、参数是否有证据、引脚是否有效；记录自动输出和人工修正两个版本。严格确认门禁是后续待补功能，不是本次下载已完成的功能。

### 6. 生成结构网表

`generate_netlists.py` 将各元件引脚投到节点标签图的连通区域，确定“哪个引脚属于哪个节点”。地优先映射为 0，其他区域分配节点编号。

典型产物：

- `outputs/test_results/<图名>/netlist_structure.txt`。
- `region_to_node_mapping.json`：区域与节点编号映射。

交叉场景还可能生成消歧图片、临时桥接标记和重新分析结果。桥接标记是算法内部处理，不是原电路真实元件。

此版本还存在读取特定 `crossing_1_line1_connected_netlist.txt` 的路径分支；多交叉点与旧产物混用需要专门验证，不能假定复杂交叉已经可靠。

### 7. 位号分配与最终网表

`generate_named_netlist()` 结合结构网表、第一轮视觉输出和 OCR 文本，再次调用模型生成命名后的网表；外层还会处理模型建议的地节点映射。

最终保存 `outputs/test_results/<图名>.txt`。此版本会插入固定的 `tran 1m 1s uic` 控制块，它不是依据你的实验需求选择的仿真设置。

检查：位号唯一性、元件是否丢失、模型是否编造、连接是否被改变、地节点是否误改、数值是否来自原图。不要把 `.end` 或分析指令的存在当作可仿真性证明。

## 四、工作区操作顺序

完成独立环境及 OCR 模型准备后，在 `SINA-Workbench` 打开 PowerShell：

```powershell
$env:SINA_ROOT = Join-Path $PWD 'SINA'
$sinaPython = '.\SINA-venv\Scripts\python.exe'
# OPENAI_API_KEY 请在当前进程中单独设置，不放进可分享日志。

& $sinaPython .\tools\probe_sina.py --root $env:SINA_ROOT
& $sinaPython .\tools\sina_lab.py --check
& $sinaPython .\tools\sina_lab.py --stage 1 -n 1 --image .\examples\user_bjt_bias.jpg
# 检查阶段 1 产物；没有通过候选图则先排查，不盲目继续。
& $sinaPython .\tools\sina_lab.py --stage 2
```

`--check` 检查文件与主要依赖，不验证 API 密钥、余额或模型访问权限，也不等于完整识别成功。

同一上游目录不要并发运行。上游数据集中未必包含你自己的目标风格，样例也不是人工标准答案。

## 五、准确率调优闭环

1. 建立目标场景数据集：清晰截图、扫描件、手机拍摄分别分组；标注元件、位号、数值、语义引脚和连接。
2. 按图纸来源和电路家族划分 train/val/test，防止近重复图泄漏。用 val 调参，test 留到最终验收。
3. 先跑官方基线，保留失败、超时、空输出和待确认项。
4. 元件检测用 `tools/validate_on_dataset.py`；完整 OCR/拓扑评估目前需人工对照，自动评估器尚待实现。
5. 每轮只修改一个因素：检测阈值/权重、分辨率、二值化/形态学参数、引脚定位、OCR 归属或模型提示词。
6. 逐图分析收益与退步，使用 `experiments/TEMPLATE.md` 记录。提示词改好不能修复所有前置漏检或错误连通。
7. 汇报分层指标与整图指标，不只报检测 F1：参数正确率、连接正确率、自动整图全对率、错误未检出率，以及耗时/成本。

比较连接时按元件语义引脚判断拓扑等价，不直接比较节点编号字符串；合法的节点重命名不应算错误。人工修正后的成绩不能混入自动识别成绩。

你最终要交付的是：**一套固定版本、固定输入范围、可重复运行、有独立测试成绩、能明确指出不确定项的识别工作流。**
