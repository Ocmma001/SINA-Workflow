# 用户显卡上的YOLO11m优化：实验001

起点：f0a0d22，独立分支opt/detector。GPU为RTX 5080 Laptop 16GB；复用本机已有环境和上游资源。
执行依据：02-detector.md。只涉及检测专项工具，不修改OCR、连接、人工确认或共享选定模型。

## 执行顺序

- [x] 起始30项工作流测试通过。
- [x] 建立独立工作目录；先验证匹配器对重复检测、错误类别、严格IoU和空预测的处理。
- [x] 固定选定权重、66图/707对象、NMS=.7，比较960/1280/1536输入；保存每图预测、图像/标签哈希及耗时。
- [x] 固定部署conf=.25，报告F1@IoU.5/.75与mAP50-95；额外阈值对照只从同一缓存计算。
- [x] 根据分辨率结果选择一次YOLO11m继续微调，最大40epoch、patience10、seed42；权重独立保存。
- [x] 对候选在相同评估尺寸下与原权重配对对比，整理坏例、退化和组员交接说明。

## 规则

66图已经用于调优，所有分辨率/阈值选择只是开发验证；不能称独立测试。
失败预测以空结果计入分母。阈值优化不能掩盖误检或严格框精度退化。
新权重仅为候选，最终是否替换要等组员的引脚/网络回归。此次训练由用户“直接开始优化”授权，不新增API调用。
大型运行输出与权重留在runs并按需通过Release交付；代码及简要评估结果进入检测分支。

## 分辨率结论与执行决定

Batch4在1536验证时显存接近占满并显著停顿，已停止该未完成扫参；全部尺寸统一batch1重跑完成。
固定conf=.25，960/1280/1536的F1@.5分别为.951524/.945329/.929307；F1@.75分别为.883657/.877509/.844200。
统一batch1的mAP50-95分别为.744971/.731453/.711942。评估batch影响矩形padding，故不把它与旧batch8的.745407误差解释为模型变动。
保留img960，开始从选定权重继续微调：AdamW、lr0=.00005、batch8、最多40轮、patience10，其他增强保持现有train_round配置。
本轮考察低学习率继续微调候选，不声称仅由学习率造成变化；继续训练本身也是变化因素。

第一组13轮早停，未超过基线mAP；按实测结果增加第二组对照，仅将Mosaic从.2改为0，起始权重、lr=.00005、img960、batch8、seed42均相同。
为避免其他电脑在高分辨率批量验证时占满显存，分辨率实验工具默认batch改为1。训练脚本默认配置仍保持兼容。

命令：

```powershell
python tools/train_round.py --name detector-exp001-train-lr5e5 --initial runs/round-002/delivery/detector.pt --baseline runs/round-002/delivery/detector.pt --epochs 40 --imgsz 960 --batch 8 --device 0 --lr0 0.00005 --patience 10
```
