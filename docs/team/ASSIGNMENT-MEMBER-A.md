# 组员A任务单：RTX 5070 Laptop / 8GB显存

分配原则：将这台电脑适合执行的优化与评估全部交给组员A；用户的RTX 5080 Laptop / 16GB显存电脑集中承担显存需求高的训练和最终候选复验。
这是任务分配，不表示已经在组员电脑上实跑通过，也不要求所有任务同时启动。

## 已知设备

根据用户提供的任务管理器截图：Windows、Intel Core i9-14900HX、16GB内存（可用总量约15.7GB）、RTX 5070 Laptop GPU、8GB专用显存、NVMe SSD。
截图中的GPU内存15.9GB包含约7.9GB共享系统内存，不能按16GB专用显存安排训练。磁盘剩余空间、当前驱动与PyTorch可用性还需组员本机检查。

## 先后顺序

1. **环境与基线**：clone源码、安装环境、导入Release资源；跑30项现有测试及一次离线识别，记录CUDA是否可用和资源占用。
2. **01数据与03 OCR**：先补真值、定位坏例，再改善文字归属/单位；这两项不需要等待新训练。
3. **04导线与05引脚**：固定检测结果，优化断线、交叉、接触点吸附；共享接触点接口由08协调。
4. **07契约与06复核**：先做离线与mock测试；API实测需本机密钥、网络及明确预算，不能把硬件可运行等同于API已可用。
5. **02推理与08集成**：复现66图检测基线、比较候选，记录完整失败与下游退化；持续集成各分区改进。
6. **小批量训练能力验证**：在上述基线完成后尝试；能跑通再决定由谁长期执行该配置。

## 本机起步验证

按[SETUP](SETUP.md)安装与导入资源。需要GPU时安装适配显卡和驱动的CUDA版PyTorch；CPU版PyTorch无法使用独显。不要根据截图中的旧驱动日期直接认定环境兼容。

```powershell
nvidia-smi
python -c "import torch; print('torch=', torch.__version__, 'cuda=', torch.version.cuda, 'available=', torch.cuda.is_available()); print(torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'CPU only')"
python -m unittest discover -s tools -p "test_*.py"
python tools/run_stage.py detector --image examples/user_bjt_bias.jpg --out runs/member-a-detector-001 --device 0 --imgsz 960
python tools/gui_workflow.py examples/user_bjt_bias.jpg --out runs/member-a-local-001
```

最后一条完整服务当前默认CPU，能验证全流程；上一条单阶段检测显式使用GPU。不要把默认CPU运行耗时当成GPU成绩。
其他阶段的独立运行见分区指南。单图成功后再顺序评估全部66张开发图，不并行启动多个CUDA进程。

## YOLO11m训练适配：先试，再分配长期任务

从选定权重开始，先保持与基线相同的imgsz=960，batch=1，2个epoch验证显存与流程：

```powershell
python tools/train_round.py --name member-a-fit-001 --initial runs/round-002/delivery/detector.pt --baseline runs/round-002/delivery/detector.pt --epochs 2 --imgsz 960 --batch 1 --device 0 --lr0 0.0002 --patience 10
```

此命令实际会做训练前验证、2轮训练和训练后验证；不是只加载模型的快速检查。它不更新全局选定权重，2轮结果也不能作为最终候选结论。
运行时用nvidia-smi/任务管理器记录峰值专用显存、系统内存、每轮耗时与是否OOM。

- 960/batch1稳定：组员可继续在这个配置训练；有明确余量时再试batch2，并记录改变后的配置。
- 960/batch1仍OOM：关闭其他GPU进程后复测；再将imgsz降至640做可运行性检查。640的结果不能直接作为960基线的提升结论；需在同一评估尺寸下对比。
- 需要更大分辨率、大batch或8GB仍无法承载：将代码、数据清单和配置交给用户的16GB显卡执行，不用共享GPU内存强撑。

训练脚本已设置workers=0、cache=False、amp=True，降低内存压力；不要未经验证改为多进程缓存全量数据。batch和imgsz的含义见[Ultralytics官方训练文档](https://docs.ultralytics.com/modes/train/)，这里的1/2只是起步配置，不是已测得的显存上限。

## 16GB系统内存的运行安排

当前截图已有约7.3GB占用。实际运行前关闭不需要的游戏、虚拟机和重型后台；一次只开一个训练或GPU推理任务，图像/评估尽量流式处理。
CPU规则开发可以多聊天分别写代码，但大批OCR、训练和全图回归顺序执行；批量API也不把全部图片同时读入内存。

## 交给用户显卡时需要提供

代码分支/commit、固定数据清单及哈希、运行命令、当前权重哈希、已做的本机检查、显存/耗时记录、预期指标和输出目录。
用户执行训练后回传逐图指标与候选权重；组员A继续做下游连接/OCR/端到端回归，最终选定权重经评测后统一更新。
