# SINA 原版提示词与豆包 Pro 对齐

## 任务保持一致

默认入口 `tools/vision_review.py` 已切换为 `--prompt-mode sina`，使用两段原版英文提示词；此前自定义复核模式保留为 `--prompt-mode review`，用于对照。

1. 从 `ocr_module.py::extract_components_from_image_api` 提取原提示词：识别实际绘制、有可见位号的元件，提取原始位号和数值、符号描述、总数与分类计数；排除地符号、导线及纯文字引用。
2. 从 `generate_netlists.py::generate_named_netlist` 提取原提示词：结合原始拓扑、第一段 LABEL:VALUE 和 OCR，匹配内部 ID 与真实位号，检查参数类型、SPICE 前缀、重复位号、模型与引脚规则，保持节点连接不变，并输出地节点建议。

原文分别保存在 `prompts/sina_inventory.txt` 和 `prompts/sina_named_netlist.txt`。`prompts/provenance.json` 记录来源函数与哈希；第二段只替换原来的三处动态输入。

## 接口与输入适配

- 原版 Chat Completions 改为火山方舟 Responses，使用已配置的 Pro 模型；不使用联网搜索。
- 保留原版 1800 / 1500 输出 Token 上限。关闭思考，非流式读取完整文本。未发送原版 temperature 字段，未验证其跨接口等价性。
- 第一阶段只发送原图；第二阶段默认只发送文本，对齐上游实际调用。`--netlist-image` 对齐原函数可选的 image_path 参数。
- 保留带下标及下划线的位号，不沿用原代码仅匹配部分 ASCII 位号的过滤限制。
- OCR 上下文保留原始文本、置信度、近邻候选，增加元件框坐标，辅助内部 ID 定位；不修改原始节点顺序和节点编号。
- 没有上游 `netlist_structure.txt` 时，从本地 CCL 候选派生原始拓扑；检测到的 GND 区域映射为 0。该拓扑尚未人工确认，不能视为真值。
- 原版允许添加通用晶体管模型和 MOSFET Bulk 节点，这些只作为模型假设，不冒充识别出的型号或连接。

## 执行

```powershell
.\SINA-venv\Scripts\python.exe tools\vision_review.py examples\user_bjt_bias.jpg --candidates runs\delivery-smoke-bjt\recognized.json --out runs\new-original-pro-test
```

若已经有上游结构网表，加 `--raw-netlist path\netlist_structure.txt`。复用第一阶段做对照可加 `--inventory-file path\API_first_response.txt`。

输出 `.cir` 是候选草稿，不自动追加分析指令、不自动补缺失值、不根据模型地节点建议修改原始拓扑。`ready_for_simulation` 始终为 false。审查会报告缺 `.end`、缺值/模型、节点或元件数量变化；它不能自动证明位号与元件位置匹配正确。

## 实测结果与限制

同一张三极管图，第一阶段正确读到四个电阻位号，但还列出了没有位号的 BJT，与原文“跳过无位号器件”的规则存在冲突。

第二阶段纯文本把 R1/R2 错配；附图也未修复该错配。补充元件框坐标后，错配改为 R1/RC。四个电阻中各有两个位号与其位置匹配，不能称为准确率提升。

以上实验保持了节点元组，但位号绑定仍可能错误。图片没有具体参数值，原版输出将值省略，所以草稿不能直接仿真；部分响应也缺少 `.end`。Q1/QMOD 属于生成的标签/通用模型，并非原图明确标注。

结论：已完成原版任务与提示词迁移；原版提示词没有自动解决匹配问题。下一步应保持这两个任务目标，对位号与图像位置建立明确映射及校验，再使用多图人工真值评估。
